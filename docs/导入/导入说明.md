# 导入与本地对齐

## 职责与入口

- `main.ts`：两个导入入口、进度和结果展示、保存最终导入记录。
- `src/noteSyncer.ts`：完整清单分页、旧编号迁移、正文与图片处理、标题和分类对齐、清理已移出导入范围的文件。
- `src/minoteApi.ts`：小米云接口；每轮实例固定域名和登录会话。
- `src/fileManager.ts`：保存目录边界校验、文件读写和移动、笔记库回收站、图片引用检查与非递归空目录清理。
- `src/settings.ts`、`src/models.ts`：持久化导入记录和移动检查点。
- `src/noteProperties.ts`：读写笔记属性，删除前核对 `noteId`。

## 数据流程

1. 固定本轮保存目录与接口会话；仅复用该完整目录下、属于当前账号或尚未登记账号的历史记录。
2. 分页获取完整笔记和分类清单。分页中断、标记异常、未知条目类型、重复或非法笔记 ID、缺失分类时，停止导入，不执行清理。
3. 使用小米云提供的 `v3SyncId` 迁移旧编号，以云端笔记 ID 关联本地相对路径。
4. 增量模式以修改时间、本地文件存在性、解密和图片补齐状态决定是否读取正文。即使跳过正文，也检查标题、目标路径并更新属性。全量模式重新读取所有正文；两种模式共用移动、写入和清理流程。
5. 完整清单中不再处于普通笔记范围的历史笔记，核对账号、文件 `noteId` 和路径占用情况后移入 `.trash`。回收站失败保留记录以便重试；文件已不存在时清理对应记录。
6. 没有待解密、图片待补或失败项时，检查受管理图片在笔记库 Markdown 中的引用；无引用图片移入回收站。最后以非递归方式移除空的旧分类目录。

## 状态归属与约束

- 导入记录仍使用 `SyncInfo`：`note` 保存 ID 与本地路径，`folder` 保存已创建的分类路径；新增 `image` 记录保存受管理图片路径。
- `account` 是域名与稳定账号编号的 SHA-256 摘要，不记录原始账号编号或额外登录凭证。无法提取稳定账号编号时禁止清理；会话切换后也禁止本轮清理。
- 文件名和标题不是身份依据。删除必须同时匹配账号、导入记录 ID 和 Markdown 的 `noteId`；不得递归删除分类目录或导入根目录。
- 移动沿用原有 `pendingMove` 检查点。如果旧路径已不存在、待移动路径存在，恢复实际文件路径，并依据已登记的源图片恢复目标图片归属；两个位置均存在时保留并报告失败。
- 旧版本无账号记录：仍在当前云端的笔记通过 ID 补齐账号；已消失的旧笔记不猜测归属，不自动删除。历史图片只有在确认对应云端附件后才建立管理记录。
- 图片清理只处理已登记的图片。直接列出并读取笔记库磁盘上的 Markdown，排除 `.trash`，避免文件索引延迟漏掉引用。插件生成的 `img/` 引用按相对路径解析；其他 Markdown、双链或 HTML 等内容出现候选图片文件名时保守保留。扫描读取失败时不继续猜测清理。
- 写入或解密失败保留原笔记和导入记录。失败的图片清理及未移除的旧分类记录继续保留，下次导入重试。
- 普通笔记范围继续排除私密笔记；已导入的笔记移入私密范围后，与移出普通笔记清单一样处理。

## 验证

- `npm test` 使用真实导入类和内存笔记库验证：两种模式完整分页、云端空清单、删除、无时间变化的改名、分类移动、同名分类和笔记、缺失文件恢复、图片共享与清理、账号切换、旧编号迁移、移动中断、回收站失败及目录边界。
- `npm run build` 检查类型并生成插件构建。
- 上述为模拟验证和构建验证；仍需在 Obsidian 与真实小米云会话中验证回收站、图片引用及实际导入数量。
